# 0.8.0rc1 — engineering memory and Cerebras release candidate

This candidate targets 0.8.0. It is not a stable qualification or a published
release. Release status is recorded in verification/runs/LATEST_CHECKS.md.

- Added sourced engineering decisions, freshness checks, bounded task context,
  scoped session/worktree storage, and review/failure memory.
- Added observational Cursor lifecycle hooks and durable MCP reconnect handles.
- Added native Cerebras SDK support alongside Groq, selected-provider setup/status,
  environment-only credentials, and provider billing/model diagnostics.
- Retained explicit saved Groq models; new configurations use the currently
  available production model openai/gpt-oss-120b. Enterprise-only model IDs must be
  selected deliberately by accounts that have access.
- Fixed legacy prose summaries/absolute file paths, graph schema-13 handling,
  transaction snapshots, current review-result chains and session export scope.
- Corrected Cursor prompt-hook continuation output and package version metadata.
- Added AGENT_MEM_STORAGE_DIR for consistent local engineering storage across
  CLI, MCP and hooks. It does not migrate existing databases.

Supported storage configuration: a local unsynchronized filesystem on one host.
Mounted-network and concurrent multi-host SQLite WAL use are excluded. Generated
hooks must be installed separately in each Python/machine environment. Native
Windows hook installation is rejected before mutation pending qualification.

Successful live Cerebras generation, full IDE lifecycle, and actual platform
runtime qualification must be recorded before stable promotion. Fixture parser
results do not establish retrieval quality, model quality, or performance savings.
